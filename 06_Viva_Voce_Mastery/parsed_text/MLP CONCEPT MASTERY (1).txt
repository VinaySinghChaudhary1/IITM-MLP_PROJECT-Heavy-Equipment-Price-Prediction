1. How to Read Python Code (Quick Refresher)
Before we touch any ML topic, you must be able to look at a 5-line Python snippet and predict what it
does. Almost every exam question shows code and asks for the output. Here are the patterns you'll
see repeatedly.
Imports — what library is being used?
import numpy as np
import pandas as pd
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LinearRegression
When you see from sklearn.X import Y, that tells you what kind of problem we're dealing with.
preprocessing = data cleaning. linear_model = regression or logistic regression. tree = decision
trees. ensemble = RandomForest, boosting. cluster = KMeans, HAC. metrics = scoring (accuracy,
f1, etc.).
The fit / transform / predict pattern
Almost every sklearn class follows this 3-step rhythm:
 fit(X, y) — "learn" from training data. Computes means, weights, splits, etc. Stores them inside
the object.
 transform(X) — apply what was learned to data (used for preprocessors like scalers,
encoders).
 predict(X) — apply what was learned to predict labels/values (used for models like
LinearRegression).
 fit_transform(X) — shortcut that does fit then transform. Use only on training data.
WATCH OUT: The most common exam trap: Calling fit_transform on test data is WRONG. On
test data you must call transform only — otherwise the test data "leaks" into the learned
parameters, which is called data leakage. Same rule for the target variable: you fit a model on
y_train, never on y_test.
Reading shape and dimensions
When code does X.shape, the answer is a tuple (rows, columns). For a 1-D array (a vector), you get
just (n,) with one number. This shows up in loaders/fetchers questions a lot.
X = np.array([[1, 2, 3], [4, 5, 6]])
X.shape   # (2, 3) — 2 rows, 3 columns
y = np.array([1, 2, 3, 4, 5])
y.shape   # (5,) — 1-D vector with 5 elements

2. NumPy in 5 Minutes
NumPy is the layer underneath everything. Every dataset in sklearn is internally a NumPy array. You
don't need to be an expert, but you must recognize these:
Creating arrays
np.array([1, 2, 3])              # 1-D array, shape (3,)
np.array([[1, 2], [3, 4]])       # 2-D array, shape (2, 2)
np.zeros((3, 4))                 # 3x4 array of zeros
np.ones((2, 5))                  # 2x5 array of ones
np.arange(10)                    # [0, 1, 2, ..., 9]
np.linspace(0, 1, 5)             # [0.0, 0.25, 0.5, 0.75, 1.0]
Indexing and slicing
a = np.array([[10, 20, 30],
              [40, 50, 60],
              [70, 80, 90]])
a[0]          # first row: [10, 20, 30]
a[:, 0]       # first column: [10, 40, 70]
a[1, 2]       # row 1, col 2: 60
a[0:2, 1:]    # first 2 rows, cols from 1 onwards: [[20, 30], [50, 60]]
NOTE: Slicing rule: start:stop — start is included, stop is NOT. So a[0:2] gives rows 0 and 1, not
2.
Reshaping
reshape(rows, cols) changes the shape without changing the data. A common need is converting a
1-D array of n elements into a column vector of shape (n, 1) before passing it to sklearn's fit method,
because sklearn expects 2-D input for X.
x = np.array([1, 2, 3, 4])
x.reshape(-1, 1)
# array([[1],
#        [2],
#        [3],
#        [4]])
# shape is now (4, 1)
# The -1 means "figure it out automatically"

3. Pandas Series & DataFrame
Pandas is the workhorse for tabular data. There are two main objects: Series (1-D, like a single
column with labels) and DataFrame (2-D, like a spreadsheet with named columns and indexed rows).
The IIT-M PYQ asks you to identify which one you're looking at — get this right.
3.1 Series — a labelled 1-D array
import pandas as pd
s = pd.Series([10, 20, 30, 40], index=['a', 'b', 'c', 'd'])
print(s)
# a    10
# b    20
# c    30
# d    40
# dtype: int64
s['b']        # 20  (label-based access)
s[1]          # 20  (position-based — works but discouraged in newer pandas)
s.values      # array([10, 20, 30, 40])
s.index       # Index(['a', 'b', 'c', 'd'])
A Series is essentially a NumPy array with a label for each element. Most things you can do to a
NumPy array (mean, sum, math operations) work on a Series too.
3.2 DataFrame — a labelled 2-D table
df = pd.DataFrame({
    'name': ['Alice', 'Bob', 'Charlie'],
    'age':  [25, 30, 35],
    'city': ['Mumbai', 'Delhi', 'Pune']
})
print(df)
#       name  age    city
# 0    Alice   25  Mumbai
# 1      Bob   30   Delhi
# 2  Charlie   35    Pune
A DataFrame is a dictionary of Series, where each Series is a column. Every column has a name (the
dictionary key). Every row has an index (default 0, 1, 2, ...).

4. Selecting Data: loc, iloc, Boolean Filtering
This is the #1 source of confusion for beginners and a frequent topic in exam code. There are three
ways to grab parts of a DataFrame:
4.1 Bracket access — quickest
df['age']             # one column, returns a Series
df[['age', 'city']]    # multiple columns, returns a DataFrame
df[0:2]                # rows 0 and 1 (slicing, NOT single index!)
WATCH OUT: Trap: df[0] does NOT give you row 0. Pandas thinks you're asking for a column
named 0, which doesn't exist — KeyError. To get rows by position, use iloc.
4.2 .loc — label-based access
.loc accesses rows and columns by their labels (index values, column names). Format:
df.loc[row_label, col_label].
df.loc[0, 'age']             # value at row label 0, column 'age' → 25
df.loc[0:2, 'name':'city']    # rows 0,1,2 ; columns from 'name' to 'city'
df.loc[:, 'age']              # all rows, just 'age' column
df.loc[df['age'] > 28]        # rows where age > 28 (boolean filter)
NOTE: Critical .loc rule: with .loc, slicing is INCLUSIVE on both ends. df.loc[0:2] gives rows 0,
1, AND 2 (three rows). This differs from regular Python slicing!
4.3 .iloc — position-based access
.iloc accesses rows and columns by their integer position (0, 1, 2, ...) regardless of what the labels
say.
df.iloc[0, 1]            # row position 0, column position 1 → 25 (age)
df.iloc[0:2, 0:2]        # first 2 rows, first 2 columns
df.iloc[-1]              # last row
df.iloc[[0, 2]]          # rows at positions 0 and 2
NOTE: Critical .iloc rule: with .iloc, slicing is EXCLUSIVE on the end (like normal Python).
df.iloc[0:2] gives rows 0 and 1 only — NOT row 2.
4.4 Boolean filtering
You can filter rows by passing a boolean Series of the same length:
mask = df['age'] > 28        # Series of True/False values
df[mask]                      # only rows where mask is True
# Combine conditions with & (and), | (or), ~ (not):
df[(df['age'] > 25) & (df['city'] == 'Pune')]
df[~df['name'].isin(['Alice', 'Bob'])]   # everyone except Alice and Bob
WATCH OUT: Use & and | (NOT 'and' / 'or'): Pandas requires the bitwise operators because it
operates element-wise on Series. Wrap each condition in parentheses, otherwise Python's operator
precedence will trip you up.

5. Dropping, Applying, and Statistics in Pandas
5.1 drop() — removing rows or columns
df.drop('age', axis=1)             # drop the 'age' column (axis=1 = columns)
df.drop(['age', 'city'], axis=1)   # drop multiple columns
df.drop(0, axis=0)                 # drop row with index 0 (axis=0 = rows)
# IMPORTANT: drop() returns a NEW DataFrame by default. The original is unchanged.
# To modify in place:
df.drop('age', axis=1, inplace=True)
NOTE: axis=0 vs axis=1: axis=0 means "go down the rows" (so you're acting on rows). axis=1
means "go across the columns" (so you're acting on columns). This trips up many students. drop
with axis=1 drops a COLUMN.
5.2 apply() — running a function on a Series or DataFrame
# Apply on a Series (one column)
df['age_doubled'] = df['age'].apply(lambda x: x * 2)
# Apply on a DataFrame, axis=0 (default): function gets each COLUMN as input
df.apply(np.mean, axis=0)
# Apply on a DataFrame, axis=1: function gets each ROW as input
df.apply(lambda row: row['age'] + 5, axis=1)

6. Introduction to Scikit-Learn
Scikit-learn (imported as sklearn) is the main ML library you'll be tested on. Its design has a few
principles that, once you understand them, make every PYQ easier.
6.1 The Estimator API
Every algorithm in sklearn is implemented as an estimator — a Python class with a consistent
interface. There are three main flavors:
 Transformers: objects that transform data. They have fit() and transform(). Examples:
StandardScaler, OneHotEncoder, PCA, SimpleImputer.
 Predictors: objects that make predictions. They have fit() and predict(). Examples:
LinearRegression, LogisticRegression, DecisionTreeClassifier, KNeighborsClassifier.
 Meta-estimators: wrap other estimators. Examples: GridSearchCV, Pipeline,
BaggingClassifier.
6.2 The fit / transform / predict pattern (in depth)
# Step 1: instantiate the estimator (set hyperparameters)
scaler = StandardScaler()
# Step 2: fit on training data (learn the mean and std)
scaler.fit(X_train)
# Step 3a: transform training data (apply learned mean/std)
X_train_scaled = scaler.transform(X_train)
# Step 3b: transform test data (apply SAME learned mean/std — don't refit!)
X_test_scaled = scaler.transform(X_test)
# Or combine fit + transform on training (shortcut):
X_train_scaled = scaler.fit_transform(X_train)
WATCH OUT: Why we never fit_transform on test data: If you do, the scaler computes a NEW
mean and std using the test data, which is information your model wasn't supposed to see during
training. This is called data leakage and inflates your test scores artificially. Exam loves this
question.
6.3 The Bunch object — sklearn's mini-dictionary
When you call load_iris(), load_digits(), fetch_california_housing(), or any of sklearn's
data-loading functions, you don't get back a DataFrame. You get a Bunch object. A Bunch is a
dictionary that also lets you access keys as attributes (with a dot).
from sklearn.datasets import load_iris
iris = load_iris()
type(iris)              # <class 'sklearn.utils.Bunch'>
# Access via dictionary-style key access:
iris['data']            # the feature matrix X
iris['target']          # the target labels y
iris['feature_names']   # column names

iris['target_names']    # class names
# Or attribute-style access:
iris.data

iris.feature_names
iris.DESCR              # long description string
NOTE: Asked every paper: 'What does load_iris() return?' Answer: a Bunch object. It contains

instead, pass as_frame=True: load_iris(as_frame=True).data is then a DataFrame.

There's also a third family — make_*
make_classification, make_regression, make_blobs, make_moons generate synthetic data on
the fly with whatever shape, noise, and class balance you want. They're for testing algorithms in
controlled conditions.
from sklearn.datasets import make_regression
X, y = make_regression(n_samples=100, n_features=3, noise=10, random_state=42)
X.shape   # (100, 3)
y.shape   # (100,)
NOTE: Common PYQ trap: 'The similarity between loaders and fetchers is...' Correct answer: both
return a Bunch object. They do NOT both load small datasets. They do NOT generate synthetic
data — that's make_*.
7.1 Splitting data into train and test
from sklearn.model_selection import train_test_split
X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,        # 20% goes to test, 80% to train
    random_state=42,      # for reproducibility
    stratify=y            # keeps class proportions balanced (classification only)
)
Important parameters
 test_size: fraction (0.2) or absolute count (50). Default 0.25.
 train_size: if you'd rather specify the train side.
 random_state: any integer; locks the shuffle so you get the same split every run. Without it,
different splits each call.
 shuffle: True by default. Set False for time-series so you don't shuffle past with future.
 stratify: when classification has imbalanced classes, pass stratify=y to keep class ratios in
train and test.

8. Handling Missing Data (Imputation)
Real datasets always have missing values (NaN). sklearn won't fit models with NaN — you must
remove or fill them first. This is imputation.
8.1 Two main strategies
 Drop rows or columns with missing values (Complete Case Analysis). Easy but loses
information.
 Fill (impute) the missing values with something reasonable: mean, median, mode, or a
predicted value.
8.2 SimpleImputer — the workhorse
from sklearn.impute import SimpleImputer
import numpy as np
# Numeric data: fill missing with the mean
imputer = SimpleImputer(strategy='mean', missing_values=np.nan)
imputer.fit(X_train)
X_train_filled = imputer.transform(X_train)
X_test_filled  = imputer.transform(X_test)   # use same fitted imputer!
Strategies of SimpleImputer
strategy What it does Use when
'mean' Fill NaN with the column mean Numeric columns, no extreme outliers
'median' Fill NaN with the column median Numeric columns, outliers present (more
robust)
'most_frequent' Fill NaN with the most common value
(mode)
Categorical columns OR numeric
'constant' Fill NaN with a fixed value passed via
fill_value=
When you want a placeholder like -1 or
'missing'
NOTE: SimpleImputer learns one number per column during fit(). For 'mean' strategy, it stores
the mean of each column in imputer.statistics_. When you call transform, it uses those stored
values to fill NaN.
8.3 KNNImputer — smarter imputation
Instead of using the column mean, KNNImputer fills a missing value by looking at the k nearest
neighbors (other rows that are most similar to the row with the missing value, based on the columns
that ARE filled), and taking their average.
from sklearn.impute import KNNImputer
imputer = KNNImputer(n_neighbors=3)
X_filled = imputer.fit_transform(X)
TIP: When KNNImputer wins: when columns are correlated (e.g., taller people weigh more, so a
missing weight can be filled from neighbors with similar heights). When columns are random and
Part 1    Page 16MLP Exam Prep — Concept Mastery Guide
uncorrelated, plain mean imputation works just as well.
8.4 Indicator columns
Sometimes the fact that a value WAS missing is itself useful information. You can pass
add_indicator=True to SimpleImputer or use MissingIndicator separately to get a boolean column
saying "this row had a missing value here."
WATCH OUT: Categorical missing data: for string columns, you cannot use 'mean' or 'median'.
Use strategy='most_frequent' or strategy='constant' with a fill_value like 'missing'.

9. Categorical Encoding
ML models work with numbers. If your data has text categories like 'Mumbai', 'Delhi', 'Pune', you must
convert them to numbers first. There are several ways, and choosing the wrong one is a classic
mistake.
9.1 OrdinalEncoder — for ordered categories
Use when categories have a natural order: Low < Medium < High, or Cold < Warm < Hot. The
encoder maps them to integers 0, 1, 2, ...
from sklearn.preprocessing import OrdinalEncoder
X = [['Low'], ['High'], ['Medium'], ['Low']]
enc = OrdinalEncoder(categories=[['Low', 'Medium', 'High']])  # specify order!
X_encoded = enc.fit_transform(X)
# array([[0.],
#        [2.],
#        [1.],
#        [0.]])
WATCH OUT: Don't use OrdinalEncoder on unordered categories like color or city! The model
will assume Mumbai=0 is somehow 'less' than Delhi=1 'less' than Pune=2, which is nonsensical and
damages your model.
9.2 OneHotEncoder — for unordered (nominal) categories
Creates one new binary column per unique category. If a row belongs to that category, the column is
1; otherwise 0. There's no false ordering implied.
from sklearn.preprocessing import OneHotEncoder
X = [['Mumbai'], ['Delhi'], ['Pune'], ['Mumbai']]
enc = OneHotEncoder(sparse_output=False)   # sparse_output=False gives a dense array
X_encoded = enc.fit_transform(X)
# array([[0., 1., 0.],   # Mumbai
#        [1., 0., 0.],   # Delhi  (alphabetical order)
#        [0., 0., 1.],   # Pune
#        [0., 1., 0.]])  # Mumbai
Important parameters
 sparse_output (was sparse in older sklearn): True returns a sparse matrix (memory-efficient
for many categories), False returns a dense NumPy array.
 drop: drop one category to avoid the dummy variable trap (relevant for linear regression).
Options: 'first', 'if_binary', None.
 handle_unknown: what to do if test data has a category never seen during fit. 'error' (default)
crashes; 'ignore' creates an all-zero row.
9.3 LabelEncoder — for the TARGET only
LabelEncoder maps each unique label to an integer. It looks similar to OrdinalEncoder but is meant
ONLY for encoding the target variable y, not features X.
from sklearn.preprocessing import LabelEncoder
Part 1    Page 18MLP Exam Prep — Concept Mastery Guide
y = ['cat', 'dog', 'cat', 'bird', 'dog']
le = LabelEncoder()
y_encoded = le.fit_transform(y)
# array([1, 2, 1, 0, 2])  # alphabetical: bird=0, cat=1, dog=2
le.classes_   # array(['bird', 'cat', 'dog'])
NOTE: The big distinction:
 OneHotEncoder → use for input features X with no order (cities, colors).
 OrdinalEncoder → use for input features X with an order (Low/Med/High).
 LabelEncoder → use for the target y in classification.

10. Numeric Transformers & Feature Scaling
Many ML algorithms care about the SCALE of features. If one feature is in the range [0, 1] (like a
probability) and another is in [0, 1,000,000] (like income), the large-scale feature dominates distance
and gradient computations. Feature scaling fixes this by transforming all features to similar ranges.
10.1 Algorithms that NEED scaling vs DON'T need scaling
Need scaling Don't need scaling
KNN (uses distance) Decision Tree
K-Means (uses distance) Random Forest
SVM (uses distance / margin) Gradient Boosting (mostly)
PCA (uses variance) Naive Bayes
Logistic Regression with L1/L2 regularization Plain Linear Regression (math is invariant, but
coefficients become hard to interpret)
Neural Networks (MLPRegressor / MLPClassifier)
Linear Regression with gradient descent
(SGDRegressor)
NOTE: Memorize this table. Direct PYQ question: 'Which algorithms don't get impacted by feature
scaling?' Answer: tree-based methods (DecisionTree, RandomForest) and Naive Bayes.
10.2 StandardScaler — Z-score normalization
Transforms each feature to have mean = 0 and standard deviation = 1. Formula: z = (x - mean) /
std.
from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_train)
scaler.mean_   # the mean of each column (learned during fit)
scaler.scale_  # the std of each column
 Pros: Most common choice. Works well with normally-distributed data.
 Cons: Sensitive to outliers — a single huge value can shift the mean and inflate std.
 Output range: NOT bounded. Most values land in roughly [-3, +3] for normal data, but extremes
can go further.
10.3 MinMaxScaler — fixed range
Transforms each feature into a fixed range, by default [0, 1]. Formula: x_scaled = (x - min) / (max -
min).
from sklearn.preprocessing import MinMaxScaler
scaler = MinMaxScaler(feature_range=(0, 1))   # default
X_scaled = scaler.fit_transform(X_train)
Part 1    Page 20MLP Exam Prep — Concept Mastery Guide
 Pros: Output is bounded, exactly between 0 and 1 (good for neural nets, image pixels).
 Cons: Very sensitive to outliers — one extreme value sets the max and squashes everything
else into a tiny range.
10.4 RobustScaler — outlier-resistant
Uses the median and the interquartile range (IQR = Q3 - Q1) instead of mean and std. Outliers don't
affect the median or IQR much, so this scaler is robust to them.
from sklearn.preprocessing import RobustScaler
scaler = RobustScaler()
X_scaled = scaler.fit_transform(X_train)
10.5 MaxAbsScaler — preserves sparsity
Divides each feature by its maximum absolute value, mapping to [-1, 1]. Doesn't shift or center the
data, so it preserves zeros — useful for sparse data.

11. Outlier Detection & Removal
An outlier is a data point that's far from most others. Outliers can wreck a model (especially linear
regression and KNN). You have two responses: remove them or use methods robust to them.
11.1 The Z-score method
Z-score tells you how many standard deviations a point is away from the mean. z = (x - mean) / std.
A common rule: any point with |z| > 3 is an outlier.
import numpy as np
mean = X.mean()
std = X.std()
z = (X - mean) / std
mask = np.abs(z) < 3      # keep only points within 3 std
X_clean = X[mask]
 Best when: data is roughly normally distributed (bell-shaped).
 Weakness: the mean and std themselves are pulled by outliers, so extreme outliers can mask
each other.
11.2 The IQR method
Compute Q1 (25th percentile) and Q3 (75th percentile). The interquartile range is IQR = Q3 - Q1. Any
point below Q1 - 1.5 × IQR or above Q3 + 1.5 × IQR is an outlier. This is the same rule used to draw
whiskers in a box plot.
Q1 = np.percentile(X, 25)
Q3 = np.percentile(X, 75)
IQR = Q3 - Q1
lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR
X_clean = X[(X >= lower) & (X <= upper)]
 Best when: data is skewed or non-normal.
 Strength: percentiles are robust — they don't get pulled by outliers.
11.3 The percentile (capping/trimming) method
Decide a percentile threshold (e.g., 1st and 99th) and either drop or cap values outside it. Capping
(also called Winsorization) replaces extremes with the threshold value instead of removing the row.
lower = np.percentile(X, 1)
upper = np.percentile(X, 99)
# Trim (drop) approach:
X_clean = X[(X >= lower) & (X <= upper)]
# Cap approach (Winsorization):
X_capped = np.clip(X, lower, upper)
NOTE: Why care about outliers in feature scaling? StandardScaler and MinMaxScaler are both
outlier-sensitive. If you scale a column with one extreme outlier, everything else gets squashed.

Either remove the outlier first, or use RobustScaler instead.

Situation Method

Data is skewed IQR (1.5 × IQR rule)
You don't trust your distribution assumptions Percentile (e.g., 1st/99th)

12. Feature Selection — Filter Methods
When your dataset has 50, 100, or 500 columns, many of them are useless or redundant. Feature
selection picks the most useful subset. There are three families:
 Filter methods: use simple statistics, no model involved. Fast and cheap.
 Wrapper methods: wrap a model and try different feature subsets. Slow but accurate.
 Embedded methods: the model itself does selection during training (like Lasso).
12.1 VarianceThreshold — drop near-constant columns
If a column has the same value in 99% of rows, it carries almost no information. VarianceThreshold
drops columns whose variance is below a threshold.
from sklearn.feature_selection import VarianceThreshold
selector = VarianceThreshold(threshold=0.1)   # drop cols with var < 0.1
X_selected = selector.fit_transform(X)
selector.get_support()    # boolean array: True = kept, False = dropped
selector.variances_       # the variance of each original column
NOTE: threshold=0 (the default) drops only columns where every row has the same value (zero
variance). Higher threshold = more aggressive dropping.
12.2 SelectKBest — keep the top k columns
SelectKBest uses a scoring function to rank each feature against the target, then keeps the top k.
The scoring function depends on whether you're doing classification or regression, and on whether
features are numeric or categorical.
from sklearn.feature_selection import SelectKBest, f_classif, f_regression, chi2, mutual_info_classif
# For classification with numeric features:
selector = SelectKBest(score_func=f_classif, k=10)
# For regression with numeric features:
selector = SelectKBest(score_func=f_regression, k=10)
# For classification with non-negative features (counts, frequencies):
selector = SelectKBest(score_func=chi2, k=10)
X_new = selector.fit_transform(X, y)
selector.scores_           # the score of each feature
selector.get_support()     # which features were kept

13. Feature Selection — Wrapper & Embedded
Methods
13.1 RFE — Recursive Feature Elimination (wrapper)
RFE is a wrapper method that uses a model's own feature importances. The procedure:
 1. Train the model on all features.
 2. Find the LEAST important feature (smallest coefficient or smallest feature_importance).
 3. Drop it. Re-train on the remaining features.
 4. Repeat until only n_features_to_select features remain.
from sklearn.feature_selection import RFE
from sklearn.linear_model import LogisticRegression
model = LogisticRegression()
selector = RFE(estimator=model, n_features_to_select=5, step=1)
selector.fit(X, y)
selector.support_      # boolean mask of selected features
selector.ranking_      # rank 1 = best, higher = eliminated earlier
selector.n_features_   # how many features were kept
NOTE: step controls how many features to remove per iteration. step=1 removes one at a time
(slow but accurate); step=5 removes five at a time (faster but coarser).
13.2 RFECV — RFE with cross-validation
Same as RFE, but uses cross-validation to automatically choose the optimal number of features
instead of requiring you to specify it.
from sklearn.feature_selection import RFECV
selector = RFECV(estimator=model, step=1, cv=5, scoring='accuracy')
selector.fit(X, y)
selector.n_features_   # the chosen number of features
13.3 SelectFromModel (embedded)
Uses any model with a coef_ or feature_importances_ attribute and keeps only features whose
importance is above a threshold. Very common with Lasso (where many coefficients become exactly
zero) and tree-based models.
from sklearn.feature_selection import SelectFromModel
from sklearn.linear_model import Lasso
model = Lasso(alpha=0.1)
selector = SelectFromModel(estimator=model, threshold='median')
X_new = selector.fit_transform(X, y)
Threshold options
 Numeric value: e.g. threshold=0.05 keeps features with importance > 0.05.
 'mean': keep features with importance above the mean importance.
 'median': keep features above median importance.
Part 2  -  Page 5MLP Exam Prep - Concept Mastery Guide
 '1.25*mean': scale factor strings are allowed.
13.4 Decision guide — which method to use
Situation Method
Quick first pass on a huge dataset VarianceThreshold + SelectKBest
Classification with discrete/count features chi2 + SelectKBest
Regression with numeric features f_regression + SelectKBest
You want the model itself to pick features Lasso + SelectFromModel (embedded)
You want best subset, can afford slow training RFE or RFECV
You don't know how many features to keep RFECV (auto-decides via CV)
TIP: Filter vs Wrapper vs Embedded summary: Filter = score each feature individually, ignore
the model. Wrapper = train the model many times with different subsets. Embedded = the model
penalizes useless features during its own training (Lasso, decision tree). Speed: filter > embedded
> wrapper. Accuracy: wrapper > embedded > filter.

14. PCA — Principal Component Analysis
PCA is the most famous dimensionality reduction technique. The goal: take your n-dimensional
data and project it into k < n dimensions, while losing as little information as possible. "Information"
here means variance.
14.1 The intuition (no math)
Imagine a cloud of 2-D points that roughly forms a diagonal line. The original axes are x and y. But
really, the data lives along a single direction (the diagonal). PCA finds that diagonal — calls it
Principal Component 1 (PC1) — and a perpendicular direction with whatever variance is left, called
PC2. If you keep only PC1, you've gone from 2-D to 1-D while keeping most of the variance.
In general, PCA produces n new axes (called principal components) ranked by how much variance
they capture. PC1 has the most variance, PC2 the second most, and so on. You keep the first k
components; the rest are discarded.
14.2 PCA in scikit-learn
from sklearn.decomposition import PCA
pca = PCA(n_components=2)
X_reduced = pca.fit_transform(X)
pca.components_              # the principal directions (each row is a component)
pca.explained_variance_      # how much variance each component captures (raw)
pca.explained_variance_ratio_  # same, as a fraction of total variance
pca.singular_values_         # the singular values from SVD
Important parameters
 n_components=k (integer): keep top k components.
 n_components=0.95 (float between 0 and 1): keep enough components to capture 95% of total
variance — sklearn picks k automatically.
 n_components='mle': use Minka's MLE to auto-pick k.
 whiten=True: after projection, divide by std so all components have unit variance. Useful for
KMeans.
14.3 explained_variance_ratio_ — the most-asked output
If you fit PCA on data with 4 features and ask for n_components=2, you'll get something like:
pca.explained_variance_ratio_
# array([0.72, 0.23])
# Means: PC1 captures 72% of variance, PC2 captures 23%.
# Together they capture 95% of the original variance.
pca.explained_variance_ratio_.sum()    # 0.95
WATCH OUT: Always scale before PCA. PCA is variance-based: a feature measured in millions
(income) will dominate one measured in 0-1 (probability). Apply StandardScaler first, always.
Part 2  -  Page 7MLP Exam Prep - Concept Mastery Guide
14.4 What does PCA NOT do
 It doesn't preserve interpretability. PC1 is some weird linear combination of all original
features. You can't easily say what it means.
 It doesn't help with non-linear structure. If your data lives on a curve, PCA (which is linear)
will struggle. Use t-SNE or UMAP for non-linear cases (but those aren't typically in this exam).
 It doesn't choose features. PCA creates new ones from combinations. If you want to keep
original feature names, use feature selection methods instead.

15. Pipelines & make_pipeline
Your preprocessing easily becomes 5+ steps: impute, encode, scale, select features, reduce
dimensions, then fit the model. Doing this manually is error-prone — you'll forget to apply scaling on
test data, or you'll fit_transform on test by accident. Pipeline fixes this by chaining everything into one
object.
15.1 The Pipeline class
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
pipe = Pipeline([
    ('imputer', SimpleImputer(strategy='mean')),
    ('scaler',  StandardScaler()),
    ('model',   LogisticRegression())
])
pipe.fit(X_train, y_train)         # fits all steps in sequence
pipe.predict(X_test)               # transforms test, then predicts
pipe.score(X_test, y_test)         # transforms test, predicts, scores
Each step is a tuple (name, estimator). The names are arbitrary but must be unique. The last step is
usually a model (predictor); all earlier steps must be transformers.
How fit and predict flow through a Pipeline
When you call pipe.fit(X_train, y_train):
 Step 1: imputer.fit_transform(X_train) — output goes to Step 2.
 Step 2: scaler.fit_transform(imputed_X) — output goes to Step 3.
 Step 3: model.fit(scaled_X, y_train) — done.
When you call pipe.predict(X_test):
 Step 1: imputer.transform(X_test) (note: transform only, no fit!)
 Step 2: scaler.transform(imputed_X)
 Step 3: model.predict(scaled_X)
TIP: This is why Pipelines prevent data leakage. They guarantee transform-only on test data
because there is no fit method called on the test set. You literally cannot make the leakage mistake.
15.2 make_pipeline — the shortcut
If you don't care about naming the steps, make_pipeline auto-generates names from the class
names (in lowercase).
from sklearn.pipeline import make_pipeline
pipe = make_pipeline(
    SimpleImputer(strategy='mean'),
    StandardScaler(),
    LogisticRegression()
)

# Equivalent to:
# Pipeline([('simpleimputer', ...), ('standardscaler', ...), ('logisticregression', ...)])

16. ColumnTransformer & FeatureUnion
Real datasets have heterogeneous columns: numeric (age, income), categorical (city, gender), and
maybe text. You need DIFFERENT preprocessing per column type. A Pipeline applies the same step
to all columns — that's not what you want here. Enter ColumnTransformer.
16.1 ColumnTransformer — different preprocessing per column
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
numeric_cols = ['age', 'income']
categorical_cols = ['city', 'gender']
numeric_pipe = Pipeline([
    ('imputer', SimpleImputer(strategy='mean')),
    ('scaler',  StandardScaler())
])
categorical_pipe = Pipeline([
    ('imputer', SimpleImputer(strategy='most_frequent')),
    ('encoder', OneHotEncoder(handle_unknown='ignore'))
])
preprocessor = ColumnTransformer([
    ('num', numeric_pipe, numeric_cols),
    ('cat', categorical_pipe, categorical_cols)
])
X_processed = preprocessor.fit_transform(X)
Each tuple is (name, transformer, columns). The transformer is applied only to the listed columns;
other columns are dropped by default.
The remainder parameter
Sets what happens to columns NOT listed in any transformer:
 remainder='drop' (default): unlisted columns are removed.
 remainder='passthrough': unlisted columns are kept as-is, untouched.
 remainder=some_transformer: apply that transformer to the rest.
ColumnTransformer([
    ('num', StandardScaler(), ['age', 'income'])
], remainder='passthrough')   # other columns kept unchanged
16.2 make_column_transformer — the shortcut
from sklearn.compose import make_column_transformer
preprocessor = make_column_transformer(
    (StandardScaler(), ['age', 'income']),
    (OneHotEncoder(), ['city', 'gender']),
    remainder='passthrough'
)
Part 2  -  Page 11MLP Exam Prep - Concept Mastery Guide
16.3 FeatureUnion — combine output of multiple transformers
FeatureUnion applies several transformers to the SAME data and concatenates their outputs
side-by-side. Different from ColumnTransformer (different columns) — FeatureUnion is same
columns, multiple views.
from sklearn.pipeline import FeatureUnion
from sklearn.decomposition import PCA
from sklearn.feature_selection import SelectKBest
union = FeatureUnion([
    ('pca',     PCA(n_components=3)),
    ('select',  SelectKBest(k=5))
])
# After fit_transform, output has 3 + 5 = 8 columns:
# 3 PCA components + 5 selected features
X_combined = union.fit_transform(X, y)
NOTE: Pipeline vs ColumnTransformer vs FeatureUnion — the most-asked PYQ
comparison:
 Pipeline = sequential. Output of step 1 → input of step 2 → ... → final model.
 ColumnTransformer = parallel on DIFFERENT columns. Each transformer touches its own
subset.
 FeatureUnion = parallel on the SAME data. All transformers see all columns; outputs
concatenate.
16.4 The end-to-end pattern
In a real ML script, you'll combine ColumnTransformer (for heterogeneous preprocessing) with
Pipeline (to attach the model at the end):
full_pipe = Pipeline([
    ('preprocessor', preprocessor),    # the ColumnTransformer
    ('model',        LogisticRegression())
])
full_pipe.fit(X_train, y_train)
full_pipe.score(X_test, y_test)

17. Linear Regression
The simplest, most-asked regression model. The idea: predict a numeric target y as a weighted sum
of the features, plus a bias term.
17.1 The model
y = w1·x1 + w2·x2 + ... + wn·xn + b
Here w1, ..., wn are the coefficients (one per feature), and b is the intercept (bias). Linear
regression learns these by minimizing the squared differences between predicted and actual values
— this is the Ordinary Least Squares (OLS) loss:
Loss = Σ (y_actual - y_predicted)2
17.2 LinearRegression in scikit-learn
from sklearn.linear_model import LinearRegression
model = LinearRegression()
model.fit(X_train, y_train)
model.coef_           # array of coefficients [w1, w2, ..., wn]
model.intercept_      # scalar b
y_pred = model.predict(X_test)
model.score(X_test, y_test)    # R squared by default
Important parameters
 fit_intercept=True (default): learn the intercept b. Set False only if your data is already
centered.
 n_jobs=-1: parallelize across cores.
 positive=True (newer sklearn): force coefficients to be non-negative.
NOTE: LinearRegression uses a closed-form solution (the normal equation: w = (X■X)■¹X■y).
It does NOT use gradient descent. For large datasets where matrix inversion is too slow, use
SGDRegressor instead.
17.3 Assumptions of linear regression
 Linearity: the relationship between X and y is approximately linear.
 Independence: observations are independent (no time-series autocorrelation).
 Homoscedasticity: residuals have constant variance across X.
 Normality of residuals: errors are roughly normally distributed (matters more for inference than
prediction).
 No multicollinearity: features aren't perfectly correlated with each other.
Part 2  -  Page 13MLP Exam Prep - Concept Mastery Guide
17.4 Multicollinearity — the silent killer
If two features are highly correlated (e.g., 'height in cm' and 'height in inches'), linear regression's
coefficients become unstable. The math doesn't fail, but tiny data changes cause coefficients to
swing wildly. Solutions: drop one redundant feature, use Ridge regression, or use PCA before
regression.
WATCH OUT: Outlier sensitivity: Plain linear regression with squared loss is heavily affected by
outliers (squaring amplifies large errors). For outlier-resistant linear models, look into
HuberRegressor or RANSACRegressor.

18. Regression Metrics
How do you score a regression model? Several metrics, each measuring something slightly different.
The exam asks you to compute these by hand or read sklearn outputs.
18.1 Mean Absolute Error (MAE)
MAE = (1/n) · Σ |y_actual - y_predicted|
The average size of error, in the same units as y. Easy to interpret. Less sensitive to outliers than
squared metrics.
from sklearn.metrics import mean_absolute_error
mae = mean_absolute_error(y_true, y_pred)
18.2 Mean Squared Error (MSE)
MSE = (1/n) · Σ (y_actual - y_predicted)2
Average squared error. Penalizes large errors heavily (because of the square). The loss function that
LinearRegression actually minimizes.
from sklearn.metrics import mean_squared_error
mse = mean_squared_error(y_true, y_pred)
18.3 Root Mean Squared Error (RMSE)
RMSE = √MSE
Just the square root of MSE, returning to the same units as y. Easier to compare to MAE because
units match.
# Older sklearn:
from sklearn.metrics import mean_squared_error
rmse = mean_squared_error(y_true, y_pred, squared=False)
# Newer sklearn (1.4+):
from sklearn.metrics import root_mean_squared_error
rmse = root_mean_squared_error(y_true, y_pred)
18.4 R2 Score (Coefficient of Determination)
R2 = 1 - (SS_residuals / SS_total)
where SS_residuals = Σ(y_actual - y_predicted)2 (your model's squared errors), and SS_total =
Σ(y_actual - y_mean)2 (total variance of the target).
Interpretation:
 R2 = 1.0: perfect predictions.
 R2 = 0.0: model is no better than predicting the mean of y for every input.
 R2 < 0: model is WORSE than predicting the mean. Yes, R2 can be negative.
from sklearn.metrics import r2_score
r2 = r2_score(y_true, y_pred)
# LinearRegression.score() returns R squared by default:
Part 2  -  Page 15MLP Exam Prep - Concept Mastery Guide
model.score(X_test, y_test)
18.5 Adjusted R2
Plain R2 has a flaw: adding more features almost always increases R2, even if those features are
useless (because the model can fit noise). Adjusted R2 penalizes extra features:
Adj R2 = 1 - (1 - R2) · (n - 1) / (n - p - 1)
where n = number of samples, p = number of features. Adjusted R2 only goes up when a new feature
actually helps. There is no built-in adjusted R2 in sklearn — compute it manually.

19. Polynomial Regression
Linear regression fits a straight line. If your true relationship is curved, a straight line won't fit well.
Polynomial regression is a clever trick: instead of changing the model, we add new features that are
powers of the original.
19.1 The trick
Suppose you have a single feature x. If you create new features x2 and x3, you now have a 3-feature
dataset. Apply plain LinearRegression to it:
y = w1·x + w2·x2 + w3·x3 + b
This is a cubic curve in x — but mathematically it's still linear in the WEIGHTS, so LinearRegression
handles it just fine.
19.2 PolynomialFeatures in sklearn
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression

# Take 1-D x -> produce features [1, x, x^2, x^3]

    PolynomialFeatures(degree=3),
    LinearRegression()
)
model.fit(X_train, y_train)
Important parameters
 degree: the highest power. degree=2 gives [1, x, x2] for one feature.
 include_bias=True (default): include the constant 1 column. Set False if your model already
adds an intercept (LinearRegression does, so you can set False to avoid duplication — both work
in practice).
 interaction_only=True: include cross-terms like x1·x2 but skip pure powers like x12.

20. Regularization: Ridge, Lasso, ElasticNet
Plain linear regression's only goal is minimizing prediction error on the training set. If features are
correlated or there are many of them, it'll learn huge wiggly coefficients that overfit. Regularization
adds a penalty on the size of coefficients to the loss function, forcing them to stay small.
20.1 Ridge regression — L2 penalty
Loss = Σ(y - y_pred)2 + α · Σ wi2
The extra term α · Σ wi2 is the L2 (squared) penalty. α (alpha) controls how strong the penalty is.
Larger α → smaller coefficients → simpler model.
from sklearn.linear_model import Ridge
model = Ridge(alpha=1.0)
model.fit(X_train, y_train)
model.coef_         # coefficients (smaller in magnitude than plain LinearRegression)
 α = 0: equivalent to plain LinearRegression.
 α → ∞: all coefficients shrink toward (but not exactly) zero.
 Default α = 1.0.
NOTE: Ridge shrinks coefficients but never sets them exactly to zero. So Ridge is good for
handling correlated features and reducing overfitting, but it doesn't do feature selection.
20.2 Lasso regression — L1 penalty
Loss = Σ(y - y_pred)2 + α · Σ |wi|
L1 uses absolute values instead of squares. The geometry of the absolute-value penalty causes
some coefficients to become exactly zero. This means Lasso performs automatic feature
selection.
from sklearn.linear_model import Lasso
model = Lasso(alpha=0.1)
model.fit(X_train, y_train)
model.coef_   # Many of these will be exactly 0
TIP: Lasso is the embedded feature selection method we mentioned earlier. Combine it with
SelectFromModel to keep only the features Lasso considered important.
20.3 ElasticNet — combine L1 + L2
ElasticNet mixes both penalties. The mixing ratio is controlled by l1_ratio:
 l1_ratio = 0: pure Ridge.
 l1_ratio = 1: pure Lasso.
 l1_ratio = 0.5: equal mix (default).
from sklearn.linear_model import ElasticNet
model = ElasticNet(alpha=0.1, l1_ratio=0.5)

21.2 SGDRegressor
Sklearn's SGDRegressor implements stochastic gradient descent for linear models. It can fit linear
regression, Ridge, Lasso, ElasticNet, and Huber — all controlled by the loss and penalty
parameters.
from sklearn.linear_model import SGDRegressor
model = SGDRegressor(
    loss='squared_error',     # 'squared_error' = OLS, 'huber' = robust
    penalty='l2',             # 'l2' = Ridge, 'l1' = Lasso, 'elasticnet' = both
    alpha=0.0001,             # regularization strength
    max_iter=1000,            # max passes over the data (epochs)
    tol=1e-3,                 # stopping criterion
    learning_rate='invscaling',
    eta0=0.01,                # initial learning rate
    random_state=42,
    shuffle=True,             # shuffle training data each epoch (default True)
    warm_start=False
)
model.fit(X_train, y_train)
Critical parameters
 loss: what to minimize. 'squared_error' for regression, 'huber' for outlier-robust regression,
'epsilon_insensitive' for SVR-style.
 penalty: regularization. 'l2', 'l1', 'elasticnet', or None.
 alpha: regularization strength (same role as alpha in Ridge/Lasso).
 max_iter: maximum number of passes through the entire training set. Each pass is called an
epoch.
 tol: stop early if loss stops improving by this much.
 learning_rate: 'constant', 'optimal', 'invscaling' (default), or 'adaptive'. Controls how the step
size changes over time.
 eta0: the initial step size when learning_rate is 'constant' or 'invscaling'.

 shuffle=True: shuffle the training data before each epoch (default and recommended).
21.3 partial_fit and warm_start — incremental learning
Two ways to continue training without losing what you've learned:
 partial_fit(X, y): trains for one epoch using the data you give it. Call repeatedly to learn from
streaming data.
 warm_start=True: when set, calling fit() again continues from the existing weights instead of
resetting. Without warm_start, every fit() restarts from scratch.
# warm_start example (asked in Dec 2025 PYQ)
model = SGDRegressor(warm_start=True, max_iter=100)
model.fit(X_batch1, y_batch1)
model.fit(X_batch2, y_batch2)   # CONTINUES from previous weights
NOTE: PYQ asked exactly this: 'How do I make fit() continue from previous weights?' Answer:
warm_start=True. Distractors like retain_parameters=True are made up and don't exist.
21.4 Why feature scaling is mandatory for SGD
Gradient descent takes steps proportional to feature magnitudes. If one feature is in [0, 1] and
another in [0, 1,000,000], the gradient is dominated by the large-scale feature, the loss surface
becomes elongated, and convergence is glacial or fails entirely. Always StandardScaler before
SGDRegressor.
WATCH OUT: Common SGDRegressor exam trap: SGD uses RANDOM samples each step.
Even with the same data, two runs may produce different coefficients unless you set
random_state. Reproducibility requires a fixed random_state.

22. Hyperparameter Tuning — A Brief Preview
Every model has knobs you set before training (called hyperparameters): alpha in Ridge,
n_neighbors in KNN, max_depth in DecisionTree, k in PCA, etc. Choosing the right values is critical.
Two main approaches:
22.1 GridSearchCV — exhaustive search
Try every combination of hyperparameter values you provide:
from sklearn.model_selection import GridSearchCV
from sklearn.linear_model import Ridge
param_grid = {
    'alpha': [0.01, 0.1, 1.0, 10.0],
    'fit_intercept': [True, False]
}
grid = GridSearchCV(Ridge(), param_grid, cv=5, scoring='neg_mean_squared_error')

grid.best_score_      # CV score of the best combination

NOTE: Counting combinations: 4 alphas × 2 fit_intercept = 8 combinations. With 5-fold CV that's
40 model fits. This counting is asked directly in PYQs.

If your grid is too large, randomly sample n_iter combinations instead of trying everything:
from sklearn.model_selection import RandomizedSearchCV

    'alpha': uniform(0.001, 10),   # uniform random between 0.001 and 10
    'fit_intercept': [True, False]
}
search = RandomizedSearchCV(Ridge(), param_dist, n_iter=20, cv=5)
search.fit(X_train, y_train)

23. Logistic Regression
Despite the name, logistic regression is a classification algorithm, not a regression algorithm. It
predicts the probability that a sample belongs to a class. It's the simplest classifier, and a great
default to try first.
23.1 The intuition
Linear regression predicts any real number: -100, 5, 1500, anything. For classification, we need an
output between 0 and 1 (a probability). Logistic regression takes a linear combination z = w1x1 +
w2x2 + ... + b and squashes it through the sigmoid function:
p = sigmoid(z) = 1 / (1 + e-z)
The sigmoid is an S-curve. It takes any real input and outputs a value between 0 and 1. Big positive z
→ close to 1. Big negative z → close to 0. z = 0 → exactly 0.5.
Decision rule
After computing the probability, you classify by thresholding (default 0.5):
 If p ≥ 0.5, predict class 1 (positive).
 If p < 0.5, predict class 0 (negative).
 You can change this threshold to trade off precision and recall.
23.2 LogisticRegression in scikit-learn
from sklearn.linear_model import LogisticRegression
model = LogisticRegression(
    penalty='l2',         # 'l1', 'l2', 'elasticnet', or None
    C=1.0,                # INVERSE of regularization strength!
    solver='lbfgs',       # the optimization algorithm
    max_iter=100,
    multi_class='auto',   # auto-picks based on data
    random_state=42
)
model.fit(X_train, y_train)
model.coef_              # shape (n_classes, n_features) for multi-class
model.intercept_         # shape (n_classes,)
model.predict(X_test)              # hard predictions (class labels)
model.predict_proba(X_test)        # probability for each class
model.score(X_test, y_test)        # accuracy
Critical parameters
 C: the INVERSE of regularization strength. Smaller C = stronger regularization. This is
opposite to alpha in Ridge/Lasso. C=1.0 is the default.
 penalty: 'l2' (default, Ridge-style), 'l1' (Lasso-style, can zero out coefficients), 'elasticnet' (mix),
or None.
 solver: optimization algorithm. 'lbfgs' (default), 'liblinear' (good for small datasets & L1), 'saga'
(large datasets, supports all penalties), 'newton-cg', 'sag'.
 max_iter: maximum iterations of the solver. Increase if you see ConvergenceWarning.
Part 3  -  Page 3MLP Exam Prep - Concept Mastery Guide
 multi_class: 'ovr' (one-vs-rest), 'multinomial' (softmax), or 'auto'.
WATCH OUT: The C confusion: In logistic regression, larger C = LESS regularization = the
model can fit more freely. In Ridge/Lasso, larger alpha = MORE regularization. These are
opposite. PYQs love this trap.
23.3 What logistic regression IS and ISN'T
Property Truth
Is it a classifier? Yes
Is it linear? Yes — the decision boundary is linear (a line/plane in feature space)
Outputs probabilities? Yes (predict_proba)
Needs feature scaling? Yes, when using regularization (so coefficients are penalized fairly)

Distractors: 'fits a curve' (no — linear boundary even though it uses sigmoid), 'minimizes MSE' (no
— minimizes log-loss / cross-entropy).

24. Classification Metrics
This is the most important section in your exam. Confusion matrix, precision, recall, F1,
ROC-AUC — these appear in EVERY paper, often multiple times. Master this and you'll bank a lot of
marks.
24.1 The Confusion Matrix
For binary classification (positive class = 1, negative class = 0), the confusion matrix is a 2x2 table
comparing predictions to actual labels:
Predicted 0 (Negative) Predicted 1 (Positive)
Actual 0 (Negative) TN (True Negative) FP (False Positive)
Actual 1 (Positive) FN (False Negative) TP (True Positive)
The four cells:
 True Positive (TP): actually 1, predicted 1 — correct positive prediction.
 True Negative (TN): actually 0, predicted 0 — correct negative prediction.
 False Positive (FP): actually 0, predicted 1 — "false alarm" / Type I error.
 False Negative (FN): actually 1, predicted 0 — "miss" / Type II error.
WATCH OUT: Sklearn convention: rows = actual, columns = predicted. So in sklearn's
confusion_matrix(y_true, y_pred), cm[0][0] = TN, cm[0][1] = FP, cm[1][0] = FN, cm[1][1] = TP.
Some books flip this (rows=predicted), so always verify.
from sklearn.metrics import confusion_matrix
cm = confusion_matrix(y_true, y_pred)
# array([[TN, FP],
#        [FN, TP]])
24.2 Accuracy
Accuracy = (TP + TN) / (TP + TN + FP + FN)
"What fraction of all predictions did I get right?"
from sklearn.metrics import accuracy_score
acc = accuracy_score(y_true, y_pred)
WATCH OUT: Accuracy is misleading for imbalanced data. If 99% of your data is class 0 and
your model predicts 0 for everything, accuracy is 99% — but the model is useless. Always check
precision/recall/F1 for imbalanced datasets.
24.3 Precision
Precision = TP / (TP + FP)
"Of all the items I PREDICTED as positive, how many were actually positive?" Measures the quality
of positive predictions. High precision = few false alarms.
Use when false positives are expensive. Example: spam filter — flagging an important email as
spam (FP) is bad. You want high precision.
Part 3  -  Page 5MLP Exam Prep - Concept Mastery Guide
24.4 Recall (Sensitivity, True Positive Rate)
Recall = TP / (TP + FN)
"Of all the items that ARE actually positive, how many did I catch?" Measures coverage. High recall
= few misses.
Use when false negatives are expensive. Example: cancer screening — missing a real cancer (FN)
is dangerous. You want high recall.
24.5 F1 Score — the harmonic mean
F1 = 2 · (Precision · Recall) / (Precision + Recall)
Combines precision and recall into one number. The harmonic mean punishes extreme values: if
either precision or recall is very low, F1 is low. Useful when you want balanced performance.
from sklearn.metrics import precision_score, recall_score, f1_score, classification_report
precision = precision_score(y_true, y_pred)
recall = recall_score(y_true, y_pred)
f1 = f1_score(y_true, y_pred)
# Get all metrics in one report:
print(classification_report(y_true, y_pred))
NOTE: Worked example (memorize this):
Suppose: TP=40, FP=10, FN=20, TN=30.
 Accuracy = (40+30)/100 = 0.70
 Precision = 40/(40+10) = 0.80
 Recall = 40/(40+20) = 0.667
 F1 = 2×(0.8×0.667)/(0.8+0.667) = 0.727

24. Classification Metrics (continued)
24.6 Specificity (True Negative Rate)
Specificity = TN / (TN + FP)
"Of all the items that ARE actually negative, how many did I correctly identify as negative?" Less
common in sklearn but appears in PYQ theoretical questions.
24.7 ROC Curve and AUC
Classifiers like LogisticRegression don't just give you a class — they give you a probability. The
default threshold of 0.5 isn't sacred. As you change the threshold, your TP rate (recall) and FP rate
change. The ROC curve plots them against each other for all possible thresholds:
 X-axis: False Positive Rate (FPR) = FP / (FP + TN)
 Y-axis: True Positive Rate (TPR) = Recall = TP / (TP + FN)
Each point on the ROC curve represents one threshold choice. The closer the curve hugs the top-left
corner, the better the model. A diagonal line is random guessing.
AUC — Area Under the (ROC) Curve
AUC is a single number summarizing the entire ROC curve:
 AUC = 1.0: perfect classifier.
 AUC = 0.5: random guessing.
 AUC < 0.5: worse than random (your labels might be flipped!)
AUC has a nice interpretation: it's the probability that the model ranks a randomly chosen positive
sample higher than a randomly chosen negative sample.
from sklearn.metrics import roc_auc_score, roc_curve
# Need probability scores, not class labels:
y_proba = model.predict_proba(X_test)[:, 1]   # probability of class 1
auc = roc_auc_score(y_test, y_proba)
# Get the actual ROC curve points:
fpr, tpr, thresholds = roc_curve(y_test, y_proba)
TIP: AUC vs Accuracy: AUC is threshold-independent (uses all thresholds). Accuracy uses only
the 0.5 threshold. AUC is more informative for imbalanced data and for comparing models.

A frequent PYQ format: "Assertion (A): This is a good model with 96% accuracy. Reason (R): For
imbalanced data, accuracy may not be a good metric."
If 96% of the data is one class, a dummy model that always predicts that class gets 96% accuracy
without learning anything. So both A and R are correct, but R does NOT explain A — in fact R
EXPLAINS WHY A IS WRONG. The trick is reading carefully.

25. Multi-class Strategies (OvR & OvO)
Some classifiers (logistic regression, SVM) are inherently binary. To handle 3+ classes, they use one
of two strategies under the hood.
25.1 One-vs-Rest (OvR), also called One-vs-All
Train n binary classifiers, one per class. Each one learns to separate "class i" from "everything
else." To predict, run all n models and pick the class with the highest confidence score.
 3-class problem → 3 binary classifiers.
 Fast: only n classifiers.
 Each classifier sees the entire dataset (one class as positive, all others as negative).
25.2 One-vs-One (OvO)
Train n × (n-1) / 2 binary classifiers, one for each pair of classes. To predict, run all classifiers and
use majority voting.
 3 classes → 3 classifiers (1-vs-2, 1-vs-3, 2-vs-3).
 4 classes → 6 classifiers.
 10 classes → 45 classifiers.
 Each classifier only sees data from its 2 classes (smaller training set per model).
25.3 Multinomial (Softmax) Logistic Regression
Logistic regression has a third option: train ONE model that natively predicts probabilities for all
classes simultaneously, using the softmax function instead of sigmoid. This is multinomial logistic
regression (a.k.a. softmax regression).
pi = ez_i / Σj ez_j
Each class gets its own linear score zi. The softmax converts those scores into probabilities that sum
to 1 across all classes.
LogisticRegression(multi_class='ovr')           # one-vs-rest
LogisticRegression(multi_class='multinomial')   # softmax
LogisticRegression(multi_class='auto')          # picks based on solver

26. K-Nearest Neighbors (KNN)
KNN is the simplest possible classifier: "to predict a new point, find the k nearest training points and
let them vote." It does NO training — it just memorizes the training data and does all the work at
prediction time. This is called a lazy learner or instance-based learner.
26.1 The algorithm
 1. Memorize all training points (X_train, y_train).
 2. For a new query point x_new:
    a. Compute distance from x_new to every training point.
    b. Find the k closest training points.
    c. For classification: majority vote among their labels. For regression: average their values.

 metric: how to measure distance. 'minkowski' is generic; with p=1 it's Manhattan, p=2 it's

 algorithm: how to find neighbors fast. 'brute' (compare to every point), 'kd_tree' / 'ball_tree'
(spatial indexes), 'auto' picks for you.

26.4 Why feature scaling is mandatory
KNN computes distances between points. If feature 1 ranges 0-1 and feature 2 ranges 0-1,000,000,

In high-dimensional space, distances stop being meaningful — all points become roughly equidistant
from each other. KNN's notion of "nearest neighbors" breaks down. Practical limit: KNN works well up
to ~10-20 features. Beyond that, use PCA first or pick a different algorithm.

27. Naive Bayes
Naive Bayes is a probabilistic classifier based on Bayes' theorem with one strong (and rarely true)
assumption: features are independent given the class. Hence "naive." Despite this naive
assumption, it works surprisingly well in practice, especially for text classification.
27.1 Bayes' theorem (the heart of it)
P(class | features) = P(features | class) · P(class) / P(features)
We want P(class | features) — "given this email, how likely is it spam?" Bayes lets us compute it from
quantities easier to estimate from training data: P(features | class) (likelihood) and P(class) (prior).
The "naive" part: assume features are independent of each other given the class, so P(x1, x2, ..., xn |
class) = P(x1|class) · P(x2|class) · ... · P(xn|class). This makes the math easy and fast.

27.5 Naive Bayes properties
 Very fast — both training and prediction. Just count and multiply.
 Works well with small data — the strong independence assumption acts as a regularizer.
 Handles multi-class natively — no OvR/OvO needed.
 NOT impacted by feature scaling — uses probabilities, not distances.
 Can struggle when features are correlated — the independence assumption is violated.
 Doesn't learn feature interactions — treats every feature independently.

28. Support Vector Machines (SVM)
SVM tries to find the best line (or curve) that separates the classes. "Best" means: maximizes the
margin, i.e., the gap between the line and the nearest points of either class. Those nearest points are
called support vectors — only they matter for the decision.
28.1 The intuition
Imagine 2 classes of points on a 2D plane. There are infinitely many lines that could separate them.
SVM picks the line with the maximum margin — the line that has the widest "street" between the two
classes. This tends to generalize better than just any separating line.
28.2 Hard-margin vs soft-margin
Hard-margin SVM: requires perfect separation. No point can be on the wrong side or inside the
margin. Only works if classes are perfectly separable, which is rare.
Soft-margin SVM: allows some points to be on the wrong side or inside the margin, but penalizes
them. The penalty strength is controlled by C:
 Large C: heavy penalty → tries hard to classify all points correctly → risks overfitting.
 Small C: lenient → allows more violations → smoother boundary, less overfitting.
28.3 The kernel trick
SVM finds linear boundaries in feature space. For non-linear problems, we transform the data into a
higher-dimensional space where it IS linearly separable. The kernel trick does this implicitly — we
never explicitly compute the higher-dimensional features, just kernel function values.

29. Decision Trees
A decision tree is a flowchart of yes/no questions about your features. "Is age > 30?" If yes, go right.
"Is income > 50K?" Each leaf node makes a final prediction. They're intuitive, interpretable, and the
building block for Random Forest and gradient boosting.
29.1 How a tree is built
 1. At each node, find the FEATURE and THRESHOLD that best splits the data into purer
groups.
 2. Apply that split, dividing the data into left and right children.
 3. Recurse: repeat the process on each child.
 4. Stop when a stopping criterion is met (max depth reached, leaf is pure enough, too few
samples).
 5. At each leaf, the prediction is the majority class (classification) or the mean (regression).
29.2 Splitting criteria — Gini and Entropy
How do we decide which feature/threshold gives the "purest" split? Two common measures of
impurity for classification:
Gini Impurity: probability of misclassifying a randomly drawn sample if you labeled it according to
the class distribution at the node. Gini = 1 - Σ pi2
Entropy: measure of disorder/uncertainty. Entropy = -Σ pi · log2(pi)
 Both are 0 when the node is pure (all one class).
 Both are maximum when classes are equally mixed.
 Gini is faster (no logarithm); they usually give similar trees.
 For regression, sklearn uses MSE or MAE as the splitting criterion.

 min_samples_split: minimum samples in a node before it can be split. Higher = simpler tree.

30. Ensemble Methods — Voting & Bagging
An ensemble combines multiple models to get better predictions than any single model. There are
two main philosophies: parallel (train models independently, combine their predictions) and
sequential (each new model fixes the previous one's mistakes — that's boosting, covered in the next
section).
30.1 VotingClassifier
Train several DIFFERENT models on the same data, then combine their predictions:
 voting='hard': each model votes for a class, majority wins.
 voting='soft': average the predicted probabilities, pick class with highest average.
from sklearn.ensemble import VotingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.svm import SVC
clf = VotingClassifier(
    estimators=[
        ('lr', LogisticRegression()),
        ('dt', DecisionTreeClassifier()),
        ('svc', SVC(probability=True))   # need probability=True for soft
    ],
    voting='soft'
)
clf.fit(X_train, y_train)
NOTE: Hard vs Soft voting: Soft voting usually performs better because it uses confidence
information, but requires all models to support predict_proba. Soft voting averages probabilities
— it does NOT pick the class with highest sum of probabilities (a common PYQ distractor).
30.2 Bagging (Bootstrap Aggregating)
Train MANY copies of the SAME model on different bootstrap samples (random samples with
replacement) of the training data. Then combine their predictions by voting (classification) or
averaging (regression).
Why does bagging help?
Each individual model might overfit to the noise in its bootstrap sample. But the noise is different
across samples, so when you average their predictions, the noise cancels out while the true signal
stays. Bagging reduces variance without increasing bias. Especially effective for high-variance
models like deep decision trees.
from sklearn.ensemble import BaggingClassifier
from sklearn.tree import DecisionTreeClassifier
clf = BaggingClassifier(
    estimator=DecisionTreeClassifier(),  # the base model
    n_estimators=100,                    # how many to train
    max_samples=1.0,                     # fraction of training samples per model
    max_features=1.0,                    # fraction of features per model
    bootstrap=True,                      # sample WITH replacement
    bootstrap_features=False,            # sample features without replacement

    oob_score=True,                      # use out-of-bag samples for validation
    n_jobs=-1,                           # parallel training
    random_state=42
)
clf.fit(X_train, y_train)
clf.oob_score_   # validation score from out-of-bag samples
Out-of-bag (OOB) score
When you bootstrap-sample a dataset, on average ~37% of samples are NOT picked. These
out-of-bag samples weren't seen by that particular tree, so we can use them as a free validation set.
Set oob_score=True to get this estimate — it's like free cross-validation.

If you set bootstrap=False, BaggingClassifier samples WITHOUT replacement — this variant is
called pasting. It's used less often than bagging.

31. Random Forest
Random Forest is bagging + decision trees + an extra trick: at each split, the tree only considers a
random subset of features. This decorrelates the trees and gives a much better ensemble than
plain bagging of trees.
31.1 Why the extra randomness?
In plain bagging of trees, all trees still have access to all features, so they tend to make similar splits
(especially picking the strongest features at the top). The trees are correlated. Adding feature
randomness at each split forces trees to be different, which makes the ensemble's variance reduction
much stronger.
31.2 RandomForestClassifier in sklearn
from sklearn.ensemble import RandomForestClassifier, RandomForestRegressor

clf.fit(X_train, y_train)
clf.feature_importances_   # average importance across all trees
clf.estimators_            # list of individual trees

 n_estimators: number of trees. More is better (up to a point), at the cost of training time.
 max_features: number of features randomly chosen at each split. 'sqrt' is the default and works

 max_depth: usually leave at None (let trees grow deep) since the ensemble averages them out.
 bootstrap=True: enables sampling with replacement (the bagging part).

32. Boosting: AdaBoost & Gradient Boosting
Boosting is the OTHER major ensemble philosophy: train models sequentially, with each new model
focusing on the mistakes of the previous ones. Done right, this turns many weak learners (slightly
better than random) into one strong learner.
32.1 AdaBoost (Adaptive Boosting)
AdaBoost trains weak classifiers (usually decision tree stumps — depth-1 trees) one at a time:
 1. Start with equal weight on every training sample.
 2. Train a weak classifier on the weighted data.
 3. Increase the weight of misclassified samples (so the next model focuses on them).
 4. Decrease the weight of correctly classified samples.
 5. Add the new model to the ensemble with a weight proportional to its accuracy.
 6. Repeat for n_estimators rounds.
Final prediction: weighted vote of all the weak classifiers.
from sklearn.ensemble import AdaBoostClassifier
from sklearn.tree import DecisionTreeClassifier
clf = AdaBoostClassifier(
    estimator=DecisionTreeClassifier(max_depth=1),  # weak learner = stump
    n_estimators=50,
    learning_rate=1.0,    # how much each new model contributes
    random_state=42
)
clf.fit(X_train, y_train)
32.2 Gradient Boosting
Gradient Boosting is more general and more powerful than AdaBoost. Instead of reweighting
samples, each new model tries to predict the residual errors of the current ensemble. The idea: the
ensemble's prediction is the sum of all models, and each new model is a small step in the direction
that reduces the loss.
Algorithm sketch:
 1. Initialize prediction as the mean of y (for regression).
 2. Compute residuals: r = y - current_prediction.
 3. Train a small tree to predict the residuals.
 4. Add learning_rate × tree's prediction to the current prediction.
 5. Repeat for n_estimators rounds.
from sklearn.ensemble import GradientBoostingClassifier, GradientBoostingRegressor
clf = GradientBoostingClassifier(
    n_estimators=100,
    learning_rate=0.1,    # smaller = need more estimators, but more accurate
    max_depth=3,          # weak learners (depth 3 trees)
    subsample=1.0,        # fraction of samples per tree (=Stochastic GB if <1)
    random_state=42
)
clf.fit(X_train, y_train)

The learning_rate / n_estimators tradeoff
learning_rate shrinks each tree's contribution. Smaller learning_rate means you need more
n_estimators to fit the data, but the result generalizes better. Common combination:
learning_rate=0.1, n_estimators=100.

33. Multi-layer Perceptron (MLP)
The MLP is the simplest feedforward neural network. It's a stack of layers: an input layer (one node
per feature), one or more hidden layers, and an output layer. Each layer applies a linear combination
followed by a non-linear activation function. This non-linearity is what lets MLPs capture complex
patterns that linear models can't.
33.1 The Perceptron — the simplest case
A single Perceptron is just step(w · x + b) — a linear classifier with a step activation. It can only learn
LINEAR decision boundaries. The famous failure: a single Perceptron can't learn XOR (which is not
linearly separable). To learn XOR you need at least one hidden layer — that's the MLP.
from sklearn.linear_model import Perceptron
clf = Perceptron(max_iter=1000, eta0=1.0, random_state=42)
clf.fit(X_train, y_train)

use TensorFlow or PyTorch. Sklearn's MLP is fine for tabular data.

Part 3 Recap — What You Now Know
 Logistic Regression: classifier despite the name. Sigmoid squashes linear scores into
probabilities. C is INVERSE of regularization.
 Confusion matrix: TP, TN, FP, FN. Sklearn convention: rows=actual, cols=predicted.
 Precision = TP/(TP+FP) (quality of positives), Recall = TP/(TP+FN) (coverage of positives), F1
= harmonic mean.
 ROC-AUC: threshold-independent metric. Plot TPR vs FPR. AUC=1 perfect, 0.5 random.
 Multi-class averaging: micro (=accuracy), macro (unweighted mean), weighted (by class size).
 OvR vs OvO: OvR = n classifiers, one per class. OvO = n(n-1)/2, one per pair. SVM uses OvO.
 KNN: lazy learner, no training. Bottleneck is prediction time. MUST scale features.
 Naive Bayes: assumes feature independence. GaussianNB (continuous), MultinomialNB
(counts), BernoulliNB (binary). NO scaling needed.
 SVM: maximum margin, support vectors only. Kernels (linear, poly, rbf, sigmoid). C = inverse
regularization. MUST scale.
 Decision Trees: greedy splits using Gini or Entropy. NO scaling needed. Easily overfit, control
with max_depth, min_samples_*.
 Voting: combine different models. Hard = majority vote on classes; Soft = average probabilities.
 Bagging: same model + bootstrap samples. Reduces variance. OOB score is free CV.
 Random Forest: bagging + random feature subsets at each split. Great default classifier.
 AdaBoost: sequential weak learners (stumps), reweight misclassified samples.
 Gradient Boosting: each tree predicts residuals. learning_rate × n_estimators tradeoff.
 MLP: stacked layers + activations. ReLU default for hidden. Output layer is auto. MUST scale.

8. The model is no better than random guessing.
9. FALSE. Soft voting averages the probabilities (or sums them, then divides by n — mathematically
equivalent for picking the max). The PYQ trap version says "sum" without explaining; check the
wording.
10. Plain bagging of decision trees. With max_features=1.0 there's no extra randomness at splits,
just the bootstrap sampling.

34. K-Means Clustering
K-Means is the most popular unsupervised algorithm. "Unsupervised" means there are no labels —
you only have X, no y. The goal: discover natural groupings (clusters) in the data. K-Means partitions
n samples into k groups, where each sample belongs to the cluster with the nearest centroid (cluster
center).
34.1 The algorithm (Lloyd's algorithm)
 1. Pick k initial centroids (randomly or smarter, see k-means++ below).
 2. Assignment step: assign each point to the nearest centroid (Euclidean distance).
 3. Update step: move each centroid to the mean of its assigned points.
 4. Repeat steps 2-3 until centroids stop moving (convergence) or max_iter is reached.
K-Means minimizes inertia (also called within-cluster sum of squares, WCSS): the total squared
distance from each point to its assigned centroid.
Inertia = Σi Σx in C_i ||x - µi||2
34.2 KMeans in scikit-learn
from sklearn.cluster import KMeans
km = KMeans(
    n_clusters=3,         # k - the number of clusters
    init='k-means++',     # 'k-means++' (smart) or 'random'
    n_init=10,            # number of times to run with different initializations
    max_iter=300,
    tol=1e-4,
    random_state=42
)
km.fit(X)
km.cluster_centers_   # shape (n_clusters, n_features) - the centroids
km.labels_            # which cluster each training point belongs to
km.inertia_           # the final WCSS (lower = tighter clusters)
km.predict(X_new)     # assign new points to clusters
Critical parameters
 n_clusters (k): you have to choose this BEFORE training. Use elbow method or silhouette
score to pick (see below).
 init='k-means++' (default): smart initialization that spreads initial centroids out. Beats random
initialization in nearly every case.
 n_init: K-Means is sensitive to initial centroids. sklearn runs the full algorithm n_init times with
different inits and keeps the best result (lowest inertia). Default 10 in older versions, 'auto' in
newer.
 max_iter: maximum iterations per run.
 tol: stop early if centroids barely move between iterations.

34.3 Choosing k — the elbow method
Plot inertia vs k for k = 1, 2, 3, ..., 10. Inertia always decreases as k grows (more clusters = tighter fit).
But there's usually an "elbow" where inertia stops dropping sharply — that's a reasonable k.
inertias = []
for k in range(1, 11):
    km = KMeans(n_clusters=k, random_state=42).fit(X)
    inertias.append(km.inertia_)
# Plot inertias and look for the elbow:
import matplotlib.pyplot as plt
plt.plot(range(1, 11), inertias, 'o-')
plt.xlabel('k'); plt.ylabel('inertia')
34.4 Silhouette score — another way to evaluate clustering
Silhouette score measures how similar each point is to its own cluster vs other clusters. For a single
point: s = (b - a) / max(a, b), where a = mean distance to points in same cluster, b = mean distance to
points in nearest other cluster.
 +1: point is far from neighboring clusters (well-clustered).
 0: point is on the boundary.
 -1: point is in the wrong cluster.
from sklearn.metrics import silhouette_score
score = silhouette_score(X, km.labels_)   # higher = better
34.5 K-Means properties
 Needs k upfront. You must choose the number of clusters in advance.
 Sensitive to feature scaling. Always scale before K-Means.
 Sensitive to outliers. One extreme point can pull a centroid far away.
 Assumes spherical, equal-sized clusters. Struggles with elongated, varying-density, or
non-convex clusters.
 Output depends on initialization. Always use k-means++ and n_init > 1.
 Fast. Linear in number of points and dimensions per iteration.
NOTE: Common PYQ: 'Which of these algorithms is impacted by feature scaling?' K-Means, KNN,
SVM, and PCA are the classic four (because all use distance/variance). Trees, Random Forest, and
Naive Bayes are NOT impacted.

35. Hierarchical Agglomerative Clustering (HAC)
HAC is a different family of clustering. Unlike K-Means, it doesn't require you to specify k upfront and
produces a dendrogram — a tree showing how clusters merge at different distances. You can cut
the dendrogram at any height to get any number of clusters.
35.1 The algorithm (bottom-up)
 1. Start with every point as its own cluster (n clusters total).
 2. Find the two CLOSEST clusters and merge them (now n-1 clusters).
 3. Repeat until you have one big cluster.
 4. Cut the resulting tree at any level to get the number of clusters you want.
There's also a top-down (divisive) variant that starts with all points in one cluster and recursively
splits. Less common in practice; sklearn implements only bottom-up (agglomerative).
35.2 Linkage criteria — how to measure distance between
clusters
When the algorithm picks the "two closest clusters," it needs a way to measure distance between two
CLUSTERS (each containing many points). Several options:

35.3 Distance metrics
Common distance/similarity metrics for HAC:
 Euclidean: straight-line distance. Default. Required for Ward linkage.
 Manhattan: sum of absolute differences.
 Cosine: angle between vectors. Good for high-dim and text.
 Jaccard: for binary/set data; intersection over union.

37. Cross-Validation
A single train/test split gives you ONE estimate of test performance, which can vary a lot based on
which samples landed in test. Cross-validation does it many times and averages, giving a more
stable estimate. It's also essential for hyperparameter tuning.
37.1 K-Fold cross-validation
Split the training data into K equal folds. For each fold, train on the other K-1 folds and validate on this
fold. You get K scores; report their mean (and std).
 Common choices: K=5 or K=10.
 Pros: uses all data for both training and validation.
 Cons: K times slower than a single train/val split.
from sklearn.model_selection import KFold, cross_val_score
kf = KFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(model, X_train, y_train, cv=kf, scoring='accuracy')
scores.mean(), scores.std()
37.2 StratifiedKFold — for classification
Like KFold, but each fold preserves the class distribution of the full dataset. Always use this instead
of plain KFold for classification — especially with imbalanced classes.
from sklearn.model_selection import StratifiedKFold
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
cross_val_score(model, X, y, cv=skf, scoring='f1')
NOTE: Sklearn shortcut: When you pass cv=5 as an integer to cross_val_score or GridSearchCV
with a CLASSIFIER, sklearn automatically uses StratifiedKFold. With a REGRESSOR, it uses plain
KFold. So cv=5 is usually safe.

38. GridSearchCV & RandomizedSearchCV
Hyperparameter tuning combined with cross-validation. These find the best parameter values for your
model by trying many combinations and using CV to score each one. Almost guaranteed to appear in
your exam.
38.1 GridSearchCV — exhaustive search
Try every combination of every value you specify.
from sklearn.model_selection import GridSearchCV
from sklearn.svm import SVC
param_grid = {
    'C': [0.1, 1, 10, 100],
    'kernel': ['linear', 'rbf'],
    'gamma': ['scale', 'auto']
}
grid = GridSearchCV(
    SVC(),
    param_grid,
    cv=5,                          # 5-fold cross-validation
    scoring='accuracy',
    n_jobs=-1,                     # parallel
    refit=True,                    # refit best on full training data (default)
    return_train_score=False
)
grid.fit(X_train, y_train)
grid.best_params_       # the winning combination
grid.best_score_        # mean CV score of the winning combination
grid.best_estimator_    # the actual fitted model with best params
grid.cv_results_        # full results dict for all combinations
38.2 Counting combinations — the math PYQs love
Total combinations = product of the lengths of all lists in param_grid. Total fits = combinations × cv
folds. Plus 1 if refit=True (default), since GridSearchCV refits the best on all training data after CV.
NOTE: Worked example: with the param_grid above, we have 4 C values × 2 kernels × 2 gammas
= 16 combinations. With cv=5, that's 80 model fits during CV, plus 1 final refit = 81 total fits. Most
PYQs ask for the combinations (16) or the total CV fits (80).
38.3 GridSearchCV with a Pipeline
When tuning a Pipeline, use the step_name__param notation:
from sklearn.pipeline import Pipeline
pipe = Pipeline([
    ('scaler', StandardScaler()),
    ('model', LogisticRegression())
])
param_grid = {

    'scaler__with_mean': [True, False]

38.4 RandomizedSearchCV — random sampling
When the grid is too large, RandomizedSearchCV samples n_iter combinations randomly. Often
finds nearly-optimal parameters in much less time.
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import uniform, randint
param_dist = {
    'C': uniform(0.001, 100),         # continuous: random float in [0.001, 100.001]
    'gamma': uniform(0.001, 1),
    'kernel': ['rbf', 'linear']        # discrete: random pick
}
search = RandomizedSearchCV(
    SVC(),
    param_dist,
    n_iter=50,                         # try 50 random combinations
    cv=5,
    random_state=42,
    n_jobs=-1
)
search.fit(X_train, y_train)

39. Transfer Learning
Transfer learning is in your syllabus (Week 12). The core idea: take a model that's already been
trained on a HUGE dataset (e.g., ImageNet for images, or BERT for text), and adapt it to YOUR
specific (usually smaller) task. You inherit all the patterns it learned without training from scratch.
39.1 Why transfer learning works
Deep neural networks learn in hierarchies. Early layers learn very general features (edges, textures,
colors for images; basic word patterns for text). Later layers learn more task-specific features. The
general features are useful for almost any related task, so we can reuse them.
39.2 Two main approaches
Feature extraction
Freeze the pre-trained model's weights and use it as a fixed feature extractor. Add a new small
classifier on top (just an output layer or a couple dense layers) and train ONLY those new layers.
 Pros: very fast, needs little data.
 Cons: the pre-trained features may not be perfectly suited to your task.
Fine-tuning
Start with the pre-trained weights but unfreeze some (or all) layers and continue training with a
SMALL learning rate. The model adapts to your data but doesn't lose what it already knew.
 Pros: often higher accuracy than feature extraction.
 Cons: needs more data and compute. Risk of overwriting useful features ("catastrophic
forgetting").
39.3 Typical transfer learning workflow
 1. Load a pre-trained model (e.g., ResNet, VGG, BERT) from a model hub.
 2. Remove the original output layer (which was for the original task).
 3. Add new output layer(s) sized for your task.
 4. Decide which layers to freeze:
     Small dataset, similar to original: freeze most, train new top.
     Small dataset, different from original: freeze early layers, retrain later.
     Large dataset, similar: fine-tune the whole thing with small lr.
     Large dataset, different: fine-tune everything; or just train from scratch.
 5. Train with a SMALL learning rate (1e-4 or smaller for fine-tuning).
NOTE: Sklearn doesn't really do transfer learning; it's a deep-learning concept. Your course
likely uses TensorFlow/Keras or PyTorch for the practical demos. For exam purposes, focus on
understanding the concept: pre-trained model + freeze/fine-tune + new task head.

40. Bias-Variance Tradeoff & Overfitting
Foundational concept. Every ML model has two sources of error beyond irreducible noise:
40.1 The two errors
Bias: the error from incorrect assumptions or oversimplified models. A linear model trying to fit a
curved relationship has high bias — it CAN'T capture the true pattern. High bias = underfitting.
Variance: the error from being too sensitive to specific training data. A super complex model that
memorizes every training point will give wildly different predictions for slightly different training sets.
High variance = overfitting.
40.2 The tradeoff
There's an inherent tension. Reducing bias usually increases variance and vice versa. The art of ML
is finding the sweet spot.
Symptom Likely cause Fix

(both bad)

underfitting

less regularization

40.3 Specific fixes for overfitting
 Get more training data (most effective when feasible).
 Reduce model complexity: shallower trees, smaller MLP, lower-degree polynomials.
 Add regularization: Ridge/Lasso for linear, max_depth/min_samples_leaf for trees, alpha for
MLP.
 Use ensembles: Random Forest reduces variance via averaging.
 Cross-validation: use it to detect overfitting and tune hyperparameters.
 Drop irrelevant features via feature selection.

43. Recommender Systems — The Big Picture
A recommender system predicts what items a user will like. Netflix recommending movies, Amazon
suggesting products, YouTube queuing up videos — all the same problem. The input is usually a
sparse user-item interaction matrix (each cell = a rating, or 1/0 for clicked/not-clicked); the output is
a ranked list of items for each user.
43.1 The user-item matrix
Imagine a table with users as rows and items (movies, products) as columns. Each cell holds a
rating (e.g., 1-5 stars) if the user has rated that item, or NaN if they haven't. The matrix is
overwhelmingly empty — most users have rated only a tiny fraction of items. The recommender's job
is to fill in the blanks.

User 3 4 5 ? ?

43.3 The cold start problem
Cold start happens when you don't have enough interaction data to make recommendations:
 New user cold start: a brand-new user has no ratings yet. Collaborative filtering can't help —
there's nothing to compare them with.
 New item cold start: a brand-new item has no ratings yet. Collaborative filtering can't help —

metadata is available immediately.

filtering. Collaborative filtering (both user-based and item-based) needs interaction data, which
doesn't exist for a brand-new item. Matrix factorization without regularization is also collaborative —
same problem.

44. Content-Based Filtering
Recommend items similar to those the user already liked, where similarity is measured using item
features (not user-user similarity). If you liked "Inception" (sci-fi, Christopher Nolan, 2010),
recommend other sci-fi Christopher Nolan films.
44.1 The procedure
 1. Build a feature vector for each item. Features can be one-hot encoded genre, TF-IDF of plot
description, director, cast, runtime, etc.
 2. Build a user profile vector by aggregating (e.g., averaging) the feature vectors of items the
user liked.
 3. For a new candidate item, compute similarity between the candidate's feature vector and the
user profile.
 4. Recommend items with the highest similarity scores.
44.2 Example
Suppose 3 movies have these one-hot encoded genre vectors:
Movie Action Comedy Romance Sci-Fi
Movie A 1 0 0 1
Movie B 0 1 1 0
Movie C 1 0 0 1
User 1 has rated Movie A highly. To find similar items, compute the similarity between Movie A's
vector [1, 0, 0, 1] and Movie B [0, 1, 1, 0] vs Movie C [1, 0, 0, 1]. Movie C is identical to A — perfect
similarity. Recommend Movie C.

45. Collaborative Filtering
Collaborative filtering ignores item metadata entirely. It works on the principle: "users who agreed in
the past will agree in the future." The only data it uses is the user-item interaction matrix.
45.1 User-User Collaborative Filtering
"Find users similar to me; recommend what THEY liked."
 1. Compute similarity between users (using their rating vectors).
 2. For each unrated item, predict your rating as a weighted average of similar users' ratings.
 3. Recommend the top-predicted items.
Example: if User 1 and User 3 both rated Movies A and B similarly, they're similar users. If User 3
loved Movie D (which User 1 hasn't seen), recommend Movie D to User 1.
Limitations of user-user CF
 Doesn't scale well: with millions of users, computing pairwise user similarities is expensive.
 Sparse data: most pairs of users have very few co-rated items, making similarities unstable.
 User tastes change over time, so similarities drift.
45.2 Item-Item Collaborative Filtering
"Find items similar to ones I've liked; recommend those."
 1. Compute similarity between items (using their column vectors of ratings).
 2. For each unrated item, predict the user's rating from similar items they HAVE rated.
 3. Recommend the top-predicted items.
Example: if Movie A and Movie C are both rated highly by the same set of users, they're similar items.
If you rated Movie A 5 stars and haven't seen Movie C, predict you'll rate C highly too.
Why item-item is preferred in practice
 Items change less often than users (new movies trickle in; new users sign up daily). Item
similarities are more stable.
 Items are usually fewer than users (Amazon has billions of users but millions of products), so
the similarity matrix is smaller.
 Recommendations are interpretable: "Customers who bought X also bought Y."

46. Cosine Similarity (Computation)
All these recommender approaches need a way to measure "similarity" between two vectors. The
most common choice is cosine similarity, which measures the angle between two vectors. The Dec
2025 PYQ Q11 asks you to compute cosine similarity by hand — you must know this formula.
46.1 The formula
cosine_similarity(a, b) = (a · b) / (||a|| · ||b||)
Breaking this down:
 a · b = dot product = a1b1 + a2b2 + ... + anbn
 ||a|| = magnitude (Euclidean norm) of a = √(a12 + a22 + ... + an2)
 ||b|| = same for b
46.2 Range and meaning
 +1: vectors point in the same direction (perfectly similar).
 0: vectors are orthogonal (no similarity).
 -1: vectors point in opposite directions (perfectly dissimilar).
For non-negative vectors (like rating vectors or one-hot features), cosine similarity is always between
0 and 1.
46.3 Worked example (the kind of question you'll see)
Item A has feature vector a = [3, 4, 0]. Item B has b = [4, 0, 3]. What's the cosine similarity?
Step 1 — Dot product:
a · b = (3)(4) + (4)(0) + (0)(3) = 12 + 0 + 0 = 12
Step 2 — Magnitudes:
||a|| = √(32 + 42 + 02) = √(9 + 16 + 0) = √25 = 5
||b|| = √(42 + 02 + 32) = √(16 + 0 + 9) = √25 = 5
Step 3 — Divide:
cosine_similarity = 12 / (5 × 5) = 12 / 25 = 0.48

47. Matrix Factorization & SVD
Matrix factorization is a more powerful collaborative filtering technique. The idea: decompose the
giant sparse user-item matrix R into the product of two smaller dense matrices — one for users (U)
and one for items (V).
47.1 The decomposition
R ≈ U × VT
Where R is the m users × n items rating matrix, U is m users × k latent factors, and V is n items ×
k latent factors. The number k is much smaller than m or n — typical k = 10 to 200.
47.2 What are "latent factors"?
Latent factors are hidden dimensions of taste that the algorithm discovers automatically. For
movies, they might roughly correspond to "action-vs-romance," "serious-vs-comedy," "old-vs-new" —
but you don't tell the algorithm what they are. Each user has a position in this k-dimensional taste
space (a row of U); each item has a position in the same space (a row of V).
To predict User i's rating for Item j: Rij ≈ Ui · Vj — the dot product of their latent vectors. If they line up
well in latent space, predicted rating is high.
47.3 SVD — Singular Value Decomposition
SVD is a classical linear algebra technique that decomposes any matrix as:
R = U × Σ × VT
Where Σ is a diagonal matrix of singular values sorted from largest to smallest. By keeping only the
top k singular values (and the corresponding columns of U and V), you get a rank-k approximation of
R that captures the dominant structure.
For recommender systems, SVD is used to reduce dimensionality of the user-item matrix, filling in
missing values implicitly. This is exactly what's asked in the Dec 2025 PYQ Q4.
NOTE: Dec 2025 Q4 PYQ: 'Performing SVD on a user-item matrix aims to:' Answer: Reduce
dimensionality. Distractors: "Increase sparsity" (no, opposite), "Delete user history" (no), "Improve
data imbalance" (no).
47.4 The big picture — matrix factorization workflow
 1. Start with the sparse user-item rating matrix R.
 2. Initialize U and V randomly.
 3. Use gradient descent to minimize the prediction error on KNOWN ratings: minimize Σ(Rij - Ui ·
Vj)2 over (i,j) where Rij is observed.
 4. Add regularization (L2 on U and V) to prevent overfitting.
 5. After training, predict ratings for unrated cells: predicted Rij = Ui · Vj.
 6. Recommend items with the highest predicted ratings.
Part 5  -  Page 9MLP Exam Prep - Concept Mastery Guide
47.5 Strengths of matrix factorization
 Captures latent structure that simple user-user / item-item similarity misses.
 Handles sparsity: works even when most cells are missing.
 Compresses the data: an m×n matrix is replaced by m×k + n×k parameters, much smaller.
 Famous winner of the 2009 Netflix Prize.
 Still suffers from cold start — new users/items have no learned latent vector.

49. Time Resampling
Resampling means changing the frequency of your data. You might have hourly data and want daily
averages, or daily data and want monthly totals. Pandas does this with the .resample() method.
49.1 Downsampling vs upsampling
 Downsampling: reduce frequency (hourly → daily). Aggregate the values: mean, sum, max,
etc.
 Upsampling: increase frequency (monthly → daily). Fill in the gaps: forward-fill, interpolation.
49.2 Resample syntax
# Daily data, downsample to monthly mean:
df.resample('M').mean()        # M = month end
df.resample('MS').mean()       # MS = month start
df.resample('Q').sum()         # Q = quarter
df.resample('Y').max()         # Y = year
# Hourly data, downsample to daily:
df.resample('D').mean()        # D = day
# Multiple aggregations at once:
df.resample('M').agg(['mean', 'sum', 'std'])
Common frequency strings (offset aliases)
Code Meaning Code Meaning
'D' Calendar day 'M' Month end
'B' Business day 'MS' Month start
'H' Hour 'Q' Quarter end
'T' or 'min' Minute 'Y' or 'A' Year end
'S' Second 'W' Week
49.3 Upsampling and filling
# Monthly to daily &#8212; need to fill new dates:
df.resample('D').ffill()         # forward-fill (carry last value forward)
df.resample('D').bfill()         # backward-fill
df.resample('D').interpolate()   # linear interpolation
df.resample('D').asfreq()        # leave as NaN

50. Decomposition: Trend, Seasonality, Residual
Decomposition splits a time series into its three components — trend, seasonality, and residual
(noise). Useful for understanding what's driving the data.
50.1 Two decomposition models
Additive model: the components add up. Use when seasonal swings are constant in absolute size,
regardless of trend level.
y(t) = Trend(t) + Seasonality(t) + Residual(t)
Multiplicative model: the components multiply. Use when seasonal swings grow or shrink with the
trend (e.g., bigger absolute swings as a business grows).
y(t) = Trend(t) × Seasonality(t) × Residual(t)
50.2 Classical Decomposition
Classical decomposition uses moving averages to estimate the trend, then subtracts (or divides) it
out and averages over seasons to estimate seasonality.
from statsmodels.tsa.seasonal import seasonal_decompose
result = seasonal_decompose(series, model='additive', period=12)
result.trend       # the estimated trend
result.seasonal    # the estimated seasonal component
result.resid       # the residual (noise) after removing both
result.plot()      # the standard 4-panel plot
Strengths and weaknesses of classical decomposition
 Simple and fast.
 Assumes seasonality is fixed (doesn't change shape over time).
 Trend is missing for the first and last few observations (because moving averages can't be
centered there).
 Sensitive to outliers.
50.3 STL Decomposition (Seasonal-Trend decomposition using
LOESS)
STL is a more flexible, modern alternative. It uses LOESS (locally weighted regression) to estimate
the trend and seasonal components, allowing them to evolve over time. It's more robust than classical
decomposition.
from statsmodels.tsa.seasonal import STL
stl = STL(series, period=12, robust=True)
result = stl.fit()
result.trend
result.seasonal
result.resid
Part 5  -  Page 15MLP Exam Prep - Concept Mastery Guide
Why STL beats classical
 Seasonality can change over time (for example, a business's seasonal pattern shifts as it
grows).
 Robust to outliers when robust=True.
 Handles any seasonal frequency, not just monthly/quarterly.
 Trend covers all observations (no missing values at the ends).
NOTE: Quick comparison:
 Classical: simple moving-average based, fixed seasonality, fast but rigid.
 STL: LOESS-based, adaptive seasonality, robust to outliers, more flexible.

51. Stationarity & the ADF Test
Stationarity is the most important concept in time series analysis. Many time-series models (ARIMA,
Holt-Winters, etc.) require stationary data to work. Understanding what stationarity means and how
to test for it is critical.
51.1 What is a stationary time series?
A series is stationary if its statistical properties don't change over time. Specifically (strict
stationarity):
 Mean is constant over time (no trend).
 Variance is constant over time (no changes in volatility).
 Autocorrelation depends only on lag, not on absolute time.
In practice, we usually care about weak (covariance) stationarity: just the first two conditions.
51.2 What does NON-stationary look like?
 Trend: mean drifts up or down over time. (e.g., a stock price climbing decade after decade.)
 Seasonality: mean varies cyclically. (e.g., ice cream sales higher in summer.)
 Heteroscedasticity: variance changes over time. (e.g., volatile periods alternating with calm
ones.)
 Random walk: each value is the previous value plus noise; variance grows with time.
51.3 The Augmented Dickey-Fuller (ADF) Test
ADF is a statistical hypothesis test that checks whether a time series is stationary.
Hypotheses:
 H0 (null hypothesis): the series is NON-stationary (has a unit root).
 H1 (alternative): the series IS stationary.
Decision rule:
 If p-value < 0.05: reject H0 → series is stationary.
 If p-value >= 0.05: fail to reject H0 → series is non-stationary.
51.4 ADF in statsmodels
from statsmodels.tsa.stattools import adfuller
result = adfuller(series)
print('ADF Statistic:', result[0])
print('p-value:', result[1])
print('Critical Values:', result[4])
# Quick decision:
if result[1] < 0.05:
    print('Stationary')
else:
    print('Non-stationary')
Part 5  -  Page 17MLP Exam Prep - Concept Mastery Guide
NOTE: Dec 2025 Q1 PYQ: 'The adfuller() function in statsmodels is used to test:' Answer: Whether
a time series is stationary. NOT seasonality (that's a different test). NOT normality. NOT
heteroscedasticity (that's the Breusch-Pagan or White test).
51.5 Handling NaN values
Most time-series functions in statsmodels (including adfuller, seasonal_decompose, STL) do not
silently impute NaNs. They will either drop them, raise an error, or return wrong results, depending
on the function. You must handle NaNs before fitting.
NOTE: Dec 2025 Q2 PYQ: 'What will typically happen if series_with_nans contains NaNs?'
Answer: fit() will raise an error or drop NaNs depending on the estimator; user should handle
NaNs beforehand. Wrong distractors: "statsmodels imputes NaNs silently" (it doesn't); "NaNs
treated as zeros" (wrong); "model uses NaNs to estimate variance" (wrong).

52. Making Non-Stationary Data Stationary
If ADF says your series is non-stationary, you transform it until it becomes stationary. Three common
techniques:
52.1 Differencing
Subtract each value from the previous one: y'(t) = y(t) - y(t-1). This removes trend. The resulting
series shows the CHANGE between consecutive points, not the absolute level.
# First-order differencing:
series_diff = series.diff().dropna()
# Second-order (apply twice if first wasn't enough):
series_diff2 = series.diff().diff().dropna()
# Test stationarity again:
adfuller(series_diff)
Most non-stationary series become stationary after one or two rounds of differencing. The
number of differences needed is called the order of integration, denoted d in ARIMA(p, d, q)
models.
52.2 Seasonal differencing
If the data is seasonal (period s), differencing at lag s removes the seasonal component:
# Yearly seasonality on monthly data: difference at lag 12
series_seasonal_diff = series.diff(periods=12).dropna()
52.3 Log transformation
If variance is increasing with the level (multiplicative pattern), take the log to stabilize it:
import numpy as np
series_log = np.log(series)
# Often combined with differencing afterwards:
series_log_diff = series_log.diff().dropna()
52.4 Detrending by regression
Fit a linear (or polynomial) regression of the series against time, then subtract the fitted trend:
from sklearn.linear_model import LinearRegression
import numpy as np
t = np.arange(len(series)).reshape(-1, 1)
trend_model = LinearRegression().fit(t, series.values)
trend = trend_model.predict(t)
detrended = series.values - trend
